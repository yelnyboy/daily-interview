# Redis 核心原理

**日期**: 2026-11-28 | **类型**: Theory | **原始分类**: 中间件 | **路线图模块**: 14-编程基础 | **难度**: 中级 | **来源**: GitHub

## 解答

Redis原理是后端面试高频考点，核心要点如下：1) 单线程模型：Redis命令执行采用单线程（IO多路复用，epoll），避免了锁竞争和上下文切换，6.0后引入多线程仅用于网络IO读写，命令执行仍单线程；2) 数据结构：底层采用SDS（简单动态字符串，O(1)获取长度、二进制安全）、跳表（zset，平均O(logN)）、压缩列表listpack（小数据节省内存）、哈希表（渐进式rehash避免阻塞）；3) 持久化：RDB定时快照（fork子进程+COW写时复制，恢复快但可能丢数据）与AOF追加日志（appendfsync everysec折中，重写机制压缩文件），4.0后支持混合持久化；4) 内存淘汰：8种策略，常用allkeys-lru（近似LRU，采样计数避免维护全量链表）；5) 高可用：主从复制（全量RDB同步+增量命令流），哨兵实现故障自动转移，Cluster分片（16384个哈希槽）；6) 缓存问题：穿透（布隆过滤器/空值缓存）、击穿（互斥锁/逻辑过期）、雪崩（随机过期时间/多级缓存）。常见追问：为什么用跳表不用红黑树；大key如何处理；Redis为什么快。

## 核心考点

- 单线程+IO多路复用
- SDS与跳表
- RDB/AOF持久化
- 主从复制与哨兵/集群
- 缓存穿透/击穿/雪崩
