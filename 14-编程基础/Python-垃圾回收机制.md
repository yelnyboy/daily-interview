# Python 垃圾回收机制

**日期**: 2026-11-06 | **类型**: Theory | **原始分类**: Python基础 | **路线图模块**: 14-编程基础 | **难度**: 中级 | **来源**: GitHub

## 解答

Python 的垃圾回收主要依赖两个机制：1) 引用计数：每个对象维护一个引用计数器，创建、赋值、传参时加 1，删除或超出作用域时减 1，计数为 0 时立即回收，这是 CPython 的主要回收方式，优点是实时性好，缺点是无法处理循环引用；2) 分代垃圾回收（gc 模块）：专门解决循环引用问题，将对象分为 0、1、2 三代，新对象在 0 代，经历过一次回收仍存活的对象晋升到下一代，0 代回收最频繁，通过减少扫描范围提升性能；3) 标记-清除算法：从根对象（全局变量、栈帧等）出发遍历引用链，不可达的对象即使存在循环引用也会被回收。关键细节：a) gc.get_threshold() 默认为 (700, 10, 10)，表示 0 代对象净增 700 个触发 0 代回收，每 10 次 0 代回收触发 1 次 1 代回收，以此类推；b) __del__ 方法在对象销毁时调用，但若对象参与循环引用且定义了 __del__，旧版本会使其不可回收（Python 3.4 后已改进）；c) 弱引用（weakref）不增加引用计数，常用于缓存；d) 性能优化中可用 gc.disable() 关闭自动回收，或 gc.freeze() 冻结长生命周期对象。常见追问：为什么有了引用计数还需要分代回收？如何排查内存泄漏（objgraph、tracemalloc）？
