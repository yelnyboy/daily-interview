# Agent 的 12-Factor 原则（第 07 条）

**日期**: 2026-11-06 | **类型**: Theory | **原始分类**: Agent基础 | **路线图模块**: 04-Agent基础与架构原则 | **难度**: 中级 | **来源**: GitHub

## 解答

背景：12-Factor Agents 是对构建可靠 LLM Agent 工程实践的经典总结，源自对生产级 Agent 系统的设计经验。核心思想包括：1) Agent 本质上是一个在循环中运行的 LLM，通过工具与环境交互；2) 工具的输入输出要结构化（如 Pydantic 模型），保证类型安全；3) 将状态作为显式的数据结构管理，而不是隐式藏在对话历史里；4) 每个组件（模型调用、工具、状态转换）都应可独立测试和替换；5) 小而专注的提示词优于一个巨大的万能提示词；6) 用代码处理确定性逻辑，用 LLM 处理模糊性；7) 错误处理要显式设计，包括重试、降级和人工介入。第 07 条通常强调的是：把 Agent 的控制流写在代码里，而不是让 LLM 决定流程。也就是说，LLM 负责理解、推理和生成，但'下一步做什么'的编排逻辑应由确定性代码控制，这样系统行为可预测、可调试、可测试。这类似于状态机模式：代码定义状态和转移规则，LLM 只在特定节点被调用。常见追问：这与 ReAct 等让模型自主决策的模式是否矛盾？实践中常采用混合方案——关键路径用代码编排，开放性任务才赋予模型自主性。

## 核心考点

- 控制流由代码而非LLM决定
- 状态显式管理
- 工具输入输出结构化
- 可测试可替换的组件
- 确定性逻辑与模糊性分离

## 常见追问

> 什么场景下应该让 LLM 自主决定下一步，什么场景下应该用代码硬编码控制流？
